## 3. Recording — the exact sequence, and the trap in it

**An application that is not in `data/applications.md` did not happen.** Record
immediately after each submission, not at the end of the session.

### 3.1 Pre-check the fuzzy match FIRST — this is not optional

`job-hunt apply` matches `(company, role)` against existing rows before creating a new
one, and **mutates the row it matches**, even across employers. On 2026-09-20 recording
"Bold AI / Forward Deployed Engineer" silently flipped **#67 Inworld AI** (a closed
April posting) to Applied, at score 0.783 — identical role title, and
`distinctive_company_name` turning both into `boldai`/`inworldai` at 0.667, over the 0.60
gate. Any `X AI` company plus a shared title collides.

```python
# uv run python - <<'PY'
from job_hunt.services.employer_match import EmployerMatcher, load_aliases
from job_hunt.repositories.tracker_repo import TrackerRepository
from pathlib import Path
m = EmployerMatcher(TrackerRepository(Path('data/applications.md')).parse(), aliases=load_aliases())
print(m.best(company='<company>', role='<role>', intent='mutate'))   # None => a new row
# PY
```

If it returns a row, record under a disambiguated company name
(`'Bold AI (experiencebold.ai)'` worked) rather than passing `--low-score-override`.

⚠️ **`tracker score 0.0/5 is below the ethical-use threshold` usually means it matched
somebody else's row**, not that the job scores badly. Investigate before overriding.

### 3.2 Record

```bash
.venv/bin/job-hunt apply '<posting url>' \
    --company '...' --role '...' \
    --pdf 'output/2026-09-21-<slug>/<resume>.pdf' \
    --no-browser --confirmed
```

`--pdf` is what stamps the row number into the `output/` directory (`.tracker-row`).
Drop the URL and keep `--no-browser` if a posting has no stable link.

### 3.3 Then write the row's notes

Submission date, acknowledgement and any stated timeline, the red-team verdict, the gap
from section 2, and the deadline. ⚠️ **Never put a literal `|` in a note** — it adds a
column and `job-hunt tracker verify` fails with `row has 10 columns, expected 9`. Write
"pipe-vs-slash" or similar.

### 3.4 Close the session

```bash
.venv/bin/job-hunt checkup
.venv/bin/job-hunt tracker verify
```

## 8. The second look — a confirmation step for everything the filters cut

Added the same day, on his instruction that the day's lessons go into the process and
that a cut be confirmed before it is lost. Rule and rationale: `CLAUDE.md` §4. Code:
`job_hunt/services/second_look.py`, `job_hunt/services/scan.py`, `tests/test_second_look.py`.

**Three places a posting was being lost, all measured:**

1. `scan`'s positive title filter. A title it does not know never reaches
   `data/pipeline.md`, so it could not be reviewed afterwards. Tested against the live
   list: *Functional Analyst*, *Database Analyst*, *IT Analyst*, *POS / Technical Support
   Specialist*, *Automation Engineer*, *AI Automation Specialist*, *Integration Engineer*,
   *GTM Engineer* all returned False. → 20 terms added to `title_filter.full.positive`, and
   anything still discarded that names an occupation is written to
   `data/scan-near-misses.tsv`.
2. The negative list matches substrings: **`Intern` discarded "Internal Tools Engineer" and
   "Software Engineer, Internal Platform"; `Sales` discarded "Salesforce Developer".** →
   `internal / international / internet / salesforce` are blanked before negatives are read.
3. `triage`: one-role-per-employer, the "large employer" exclusion, and a generic title
   ranking below the cut (this is where Beacon was). → `job-hunt triage --second-look N`
   reads the posting body and sorts each row into *the posting argues for it* / *cut
   confirmed* / *no signal* / *could not be read*.

A rescue needs a **strong** signal (agentic or LLM work, AI coding tools named, automating
manual work, Chinese asked for) and no kill signal (5+ years, co-op, French, clearance,
management level, named-stack depth, a French-language posting, a domain credential).
Level and "works with business users" only support — alone they rescued a BMO *Personal
Banking Associate* on the first run.

**First live run, 80 rows:** 15 rescued · 37 cuts confirmed · 23 no signal · 5 unreadable.
Worth reading from the rescued list: AppDirect *Revenue Ops Systems Analyst* (agentic +
automation + business users; #957 is open there), Big Viking Games *software developer*
